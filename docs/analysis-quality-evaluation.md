# 分析质量回归

测试使用家庭电脑的 qwen3.5:9b 和原生 Ollama，规划、报告及校对温度零、关闭推理。原版基线使用 32768 上下文；调优候选使用 8192 上下文、32 个 GPU 层和 60 秒空闲驻留。账本和对话存储均为合成替身，不读取真实用户账本。合成账本包含六个完整月份及本月，月工资 5000、家教 1600、房租 1800、餐饮 600、交通 200，上个完整月另有医疗 900。

## 验收口径

| 场景 | 必须满足 |
| --- | --- |
| 综合诊断 | 完整月平均支出 2750、结余 3850；不能替换成中位数 |
| 支出变化 | 医疗增加 900 解释最近完整月份变化，不能推断以后不会发生 |
| 收入韧性 | 工资占持续性历史收入 75.76%；缺少可动用余额及冲击幅度，不给承受月数 |
| 多月展望 | 从下个月起三个完整月，基准新增结余 12000，带条件说明 |
| 每月多留 1000 | 保留必要支出后没有已识别的候选空间，不能强行削减生活费 |
| 购买电脑 6000 | 缺少余额时不作确定购买能力判断 |
| 从 10000 存到 20000 | 三个月条件余额 22000；所需月结余 3333.33，不等于额外节支缺口 |
| 数据质量 | 医疗样本不足；规则未命中不能证明账本无错、完整 |
| 连续追问 | 三个月 12000 → 家教减半 9600 → 保留房租餐饮 → 五个月 16000；月度结余仍为 3200 |
| 来源变体 | 家教减少 30%，其他不变，三个月新增结余 10560 |
| 购买变体 | 可用 12000，购买 6000，保留应急金 5000：买后 6000，超过储备底线 1000；仍需确认近期必付账单 |
| 目标变体 | 当前 10000、目标 20000、未给期限：历史月结余条件下约 3 个月 |
| 中断变体 | 全部收入停止、可用 10000、支出延续：每月缺口 2600，约可覆盖 3.85 个月 |

程序检查金额、条件、状态与回答是否包含核心结果；人工复核还要检查事实与推断、是否回答问题、建议能否执行及是否误导。`reviewed` 只是模型审查通过，不是正确性的证明。`verified_facts_fallback` 计为未通过分析质量验收。

## 发现与修正

- 原版把家教少一半当作减少 50 元，追问丢失假设；新增按来源百分比计算、结构化上下文及期限增量。
- 原版用月结余除以月支出推算能撑多久；购买与现金承受时长现在必须有可动用余额。
- 原版将未检出异常解释为排除记账错误；数据质量工具保留样本和规则边界。
- 报告生成曾丢掉必要条件、引入未经计算的数字；现在恢复必要引用，移除模型另写的数量句，对剩余解释另行审查，失败反馈携带原稿重试。
- 模型空字段输出曾导致优化、目标问题规划失败；仅归一化无含义的可选空字段，不填补未知财务条件。
- 目标规划曾把所需月结余当作额外节支；目标差额由工具根据基准重新计算。
- 审查深度推理试验耗时明显增加并出现输出截断，未采用该设置。
- 独立代码审查发现并修复了并列情景与查询范围之间的条件串用、隐式查询范围不明确、同来源多个增量丢失、部分月份误作完整样本、储蓄期限未展示等问题。
- 人工复核发现“建议”句中也可能包含无依据的前提，例如先称医疗费为一次性再建议剔除。解释校验增加这类边界，零候选项时仍提供核查、增收或期限调整的下一步。
- 购买日期曾被放进历史查询窗口。带未来决策的计划现在改用历史基准并记录修正；纯历史查询误填未来范围仍拒绝执行。
- 未见过的变体暴露了应急储备被误作储蓄目标、明确全部停薪却未提取冲击的问题。Schema 补充字段语义，对单一范围内明确、无歧义的条件作归一化，否定句、并列情景和不同查询范围不全局套用。

- 确定性与接口回归共 109 项通过，涵盖查询授权、会话历史、SSE、计算、条件隔离和报告边界；前端构建通过。
- 最近完整模型批次 `iteration11-gpu32.jsonl` 为 15/16 自动通过，停薪题因数字复述导致解释被全部移除而退化为事实输出。人工复核另发现重复线索、历史窗口和购买措辞的问题，没有把自动通过当成最终结论。
- 修复后，`iteration13-targeted.jsonl` 中综合诊断、购买、储蓄目标、购买储备及停薪五题全部通过；`iteration14-drivers.jsonl` 中变化归因复测通过。汇总覆盖的 16 个场景均已有通过记录；这是完整批次加受影响场景的定向复测，并非宣称最终提交重新全量运行了一遍。
- 当前渲染校验还重放了完整批次的 16 份模型草稿；条件动作可以保留，未经核算的数量和无依据的结论被移除。原始草稿与修正记录保留用于诊断。
- [实际问答全文](analysis-quality-examples.md) 保留每题的问题、回答、耗时和采集批次，均为合成财务数据。

完整批次耗时 20.35～60.77 秒，中位数 27.08 秒。在当时共享显卡负载下，显存峰值 9808 MiB、最低空闲 2067 MiB，测试错误日志为空。采用 8K 上下文、`OLLAMA_NUM_GPU=32`、`OLLAMA_KEEP_ALIVE=60s`。其他 GPU 任务会改变余量；缩短驻留只释放空闲占用，不能保证并发峰值不溢出。24 层试验的综合诊断耗时约 138 秒，因此没有采用该更慢的配置。

本轮没有接入真实用户账本，也没有验证手机 WebView。模型仍可能给出重复、笼统或未覆盖规则边界的解释；`reviewed` 不是正确性的证明。后续应结合实际使用反馈、存储的结构化条件、工具证据和报告校对记录继续回归。
